## 四、发现的问题

### 1. 「全局搜索」没有独立入口（功能缺口）

`ProjectSearchDialog` 固定作用于项目根目录，窗口标题写死 `Search in Project — <项目名>`（`ProjectSearchDialog.cpp:169`），对话框内只有 关键字 / 大小写 / 全词 / 正则 四个控件，**没有搜索范围切换**。

清单里"全局搜索 / 文件内搜索 / 项目中搜索"三项，实际只有两种范围：当前文件（FindBar）与当前项目（ProjectSearchDialog）。如果"全局搜索"指的是"跨所有已打开文档搜索"，该能力目前不存在。

建议：在 `ProjectSearchDialog` 增加范围下拉（当前文件 / 已打开文档 / 整个项目），或让"已打开文档"走内存缓冲区而不是磁盘。

### 2. 「查找符号」只覆盖当前文件

`showSymbolSearch()` 用的是 `outlineEntries_`（当前文件的 clangd `documentSymbol` 结果），切标签后还会失效并提示"再按一次 Ctrl+Shift+O"。

真正的"查找符号"通常是工作区级（VS Code 的 `Ctrl+T`、`workspace/symbol`）。当前实现等同于"文件内符号跳转"，功能名与能力不匹配。

建议：新增 `workspace/symbol` 请求，或把该菜单项改名为「转到文件内符号」。

### 3. 只读状态无界面常驻提示

只读文件只在输出面板打一行 `Read-only: <path>`，选项卡和状态栏没有任何标记。用户切走后无法知道该文件不可编辑，直到按 Ctrl+S 报错。

建议：只读文件的选项卡标题加"(只读)"后缀，或状态栏加锁定图标。

### 4. 测试目标无法编译（阻塞 CI）

`tests/LightCppPluginTests/PluginManagerTests.cpp`：

- `:336` `std::make_unique<TrackedPlugin>(...)` 报 `template argument 1 is invalid`（`TrackedPlugin` 在该 TU 内不可完整构造，疑为抽象类或类型未定义）
- `:60` `writeDevProject` 未使用、`:71` `kDevFixture` 未使用，在 `-Werror` 下升级为错误

后果：`ctest` 无法运行，功能回归失去自动化保障。应用本体不受影响（`lightcpp` 已构建成功）。
