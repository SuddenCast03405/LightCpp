| 编号 | 级别 | 模块 | 位置 | 问题 | GUI 表现 |

| R2-01 | 致命 | LSP 客户端 | `LanguageServerClient.cpp:1033-1035` | `emit serverFailed` 之后仍 `process_->kill()`；接收端 `MainWindow.cpp:541` 的 `actSyntaxCheck_->setChecked(false)` 会同步走 `onSyntaxCheckToggled→stop()`，后者 `delete proc` 并把 `process_` 置空 | 服务器对 `initialize` 回 error 时 IDE **立即空指针崩溃**，且无日志 |

**A 节已清零（第十三批 `0c17ec4`）** —— R2-01/R2-02 同一根因，已修：

`serverFailed` 的接收端（`MainWindow.cpp:541`）会**同步**走 `setChecked(false)` → `onSyntaxCheckToggled(false)` → `lsp_->stop()` → `delete proc`。三条路径都在 `emit` 之后继续使用那个 QProcess：

1. `errorOccurred(FailedToStart)` 由 Qt **在 `QProcess::start()` 内部**同步投递；处理器把进程删掉后，Qt 继续在已释放内存上跑 `startProcess()`。本机复现就是"启动即崩"：`0xC0000005`，gdb 栈 `LanguageServerClient.cpp:423` ← `MainWindow::onSyntaxCheckToggled` ← `MainWindow::MainWindow:696`。触发条件是沙箱下 QProcess 命名管道 `ERROR_PIPE_BUSY`（与 `windeployqt` 同一环境问题），也就是这段时间离屏冒烟一直报的崩溃——**它并非本节之外的偶发，正是本根因**。
2. `initialize` 返回 error 的分支：`emit` 之后又 `process_->kill()`（上一轮 `L-1` 修复引入）。
3. `finished` 槽：`emit` 之后又 `p->deleteLater()`，`p` 可能已被 `stop()` 删除。

修法：统一走新的 `reportServerFailure()` —— **先摘链再通知**（`process_ = nullptr`、`disconnect(this)`、`kill()`、`deleteLater()`），并把 `serverFailed` 用 `Qt::QueuedConnection` 投递，使拆除动作一定等 `QProcess` 的调用栈退栈之后才执行；`finished` 槽先读 `exitCode`/`!everInitialized_` 再摘链；`errorOccurred` 槽忽略过期 `sender()`。验证：0 警告 + ctest 333/333 + 离屏冒烟 ALIVE×3，且**修复前必崩的同一条 gdb 运行现在带同样的管道失败存活满 40s**（A/B 对照）。

R2-08 的修法（补全重试把"进程活着"当成"握手完成"）：`scheduleCompletionRetry()` 原先在 400 ms 后跑

```
if (!lsp_->isRunning()) { lsp_->start(); }
if (!lsp_->isRunning()) { return; }      // 恒为真
```

而 `isRunning() = 进程在跑 && initialized_`，`start()` 只**开始**一次异步握手 —— 于是第二道判断在每次真正需要重试的时候都会 return：重试预算被 `++completionAttempts_` 烧掉、服务器**一次都没被问过**，Ctrl+Space 弹出完全空白且无任何提示。`requestCompletionFor()` 的首个请求有同一个洞（对未握手的客户端调 `requestCompletion` 直接返回 0，请求被客户端丢弃）—— 这正是"clangd 崩溃/重启后第一次补全什么都不发生"的原因。分三层修：

- **机制层（可测）**：纯逻辑层新增 `Core::ReadyGate`（`src/LightCppCore/Include/LightCpp/Core/ReadyGate.hpp` + `Source/ReadyGate.cpp`）——一次性的就绪闩 + 回调队列：`whenReady()` 开着就当场跑、否则排队；`open()` 按排队顺序排空；`drop()` 丢弃**且不跑**（它等的那个握手不会来了）。Qt-free，`LightCppCoreTests/ReadyGateTests.cpp` 8 条用例：立即跑 / 排队后按序跑 / drop 不跑且不被下一次 open 复活 / 第二次 open 什么都不跑 / 回调里再排队立即跑 / 回调里 drop 会放弃其后所有回调 / 空回调被忽略 / 已开门时空回调不吞掉真回调。
- **客户端层**：`LanguageServerClient` 暴露 `whenReady()`（await 形式："服务器可用了就把这件事办了"）与 `isStarting()`（进程已起、尚不可用），并把闩接在每个状态边沿：`initialize` 应答里 `emit serverStarted()` **之后**才 `open()`（排队的请求因此看到的是"启动"处理已经打开过的那些文档），`start()` / `stop()` / `reportServerFailure()` / 进程退出都 `drop()`。`isStarting()` 用 `process_ != nullptr && !initialized_` 而**不是** `state() == Running`：`start()` 不等进程，最初几个事件循环里状态还是 `Starting`，只认 Running 会恰好在它存在的那个窗口里答"没有"。顺带修掉一个相邻隐患：重启后**旧进程**的 `finished` 不再清掉**新**握手的 `initialized_`（原来会留下一个"进程活着但客户端永远说不上话"的服务器）。
- **主窗口层**：`requestCompletionFor()` 与重试共用 `requestLspCompletion()`（同一条 `changeDocument` → `requestCompletion` 协议路径），未就绪时统一改挂 ready 边沿；`PendingCompletion` 加 generation 戳，排队回调发现自己已被更新的请求（或标签页已关）替换就放弃 —— 否则它会替别人的弹窗发问、还吃掉新请求的重试预算。重试预算耗尽而服务器仍未起来时，状态栏给出 `Completion unavailable: the language server is not running`，不再是"空白弹窗 + 零提示"。

R2-08 的验证：0 警告，ctest 389 → **397**（+8 ReadyGate），离屏启动冒烟 ALIVE×3。App 层无套件，另建探针 `.workbuddy/_probe_whenready.ps1`（源码 `_whenready_probe.cpp`，直接链 `LanguageServerClient.cpp` + `libLightCppCore.a`）驱动**真 clangd**：本机沙箱起不了子进程（`QProcess` 报 `pipe: …`，与 `CodeFormatterProcess` 三条用例被 SKIP 同因），探针先探测这一点，依赖真握手的 4 条（`start()` 返回时 `isRunning` 假而 `isStarting` 真、未握手 `requestCompletion` 返回 0、排队回调在握手落地后跑到、握手后同一请求拿到正数 id）自动 SKIP 并打印原因；不依赖子进程的 3 条照跑并 PASS（`start()` 失败时丢掉排队请求而不是跑它、失败后既不 running 也不 starting —— 这正是重试链能继续推进的前提、再次 `start()` 不复活旧请求）。

- **R2-28**（项目声明不编译的单元被按对象名引用）：`Compile=0/Link=1` 的语义是"不要构建它，但要链接它"。这种单元此前照走"对象名变换"，于是 `icon.res` 被写成 `icon.o` —— 一个既没有任何规则能生成、也不存在的目标，make 直接拒了整个构建。**改法：我们不编译的单元，就用项目给出的那个文件名去链接**；只有**源文件**才保留对象名（对源文件而言 `Compile=0/Link=1` 只能读成"链接别的构建产出的那个 `.o`"）。
