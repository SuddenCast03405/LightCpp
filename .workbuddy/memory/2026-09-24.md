## 顺带修掉一个既有真 bug：数字高亮正则一直是无效的
- `CppSyntaxHighlighter` 的数字规则 `\b(...)?)|(...)|...)\b` 多了一个 `)`，
  Qt 报 `unmatched closing parenthesis` → 整条规则被 QSyntaxHighlighter 静默跳过，
  数字从来没被高亮过，而且每次重绘都往 stderr 刷 "called on an invalid QRegularExpression object"。
- 修复 = 把 alternation 收进外层 `\b(...)\b` 组（删掉一个括号）。用最小 Qt 程序验证：
  旧串 invalid / 新串 valid，且能匹配 42、0xFF、0b1010、1.5e3、10u、1'000，不误匹配标识符。

## 编译运行 / 直接运行（Tools 菜单）
用户诉求：加「编译运行」，加「直接运行」（没编译过要提示）。

- 新增三个 QAction：`Compile & Run`(F5) / `Run`(Ctrl+F5) / `Stop Program`(Shift+F5)，
  Tools 菜单 + 工具栏各出现一次；原有的 `Compile Current File`(F7) 保持只编译。
- **编译与运行共用 `BuildTarget resolveBuildTarget(editor)`**（srcPath / exePath / tempSource）：
  已保存文件 → exe 在源文件同目录同名；未保存 Untitled → 源码写
  `%TEMP%/lightcpp-compile/<tabstem>.cpp`，exe 同目录。这样「运行」永远找「编译」写出的位置，
  两边逻辑不会漂移（以前 exe 路径是在编译函数里现算的）。
- `onCompileAndRun()` = 置 `runAfterBuild_ = true` 再调 `onCompileCurrentFile()`；
  编译进程的 `finished` 回调里看 rc==0 才 `startProgram(lastBuildExe_, 源目录)`，
  失败则打印 "Build failed — nothing was run."，不会再残留 pending 状态。
- `onRunCurrentFile()`：exe 不存在 → Build Log 里先说明「尚未编译」，
  再弹 `QMessageBox::question` 问「现在编译并运行吗？」，Yes 走编译运行、No 打印 F5 提示。
  exe 存在但比源码旧（或缓冲 modified）→ 打印一行 "source is older … press F5 to rebuild" 提醒，
  仍然照跑（对齐 VS 的 Ctrl+F5 语义）。
- `startProgram()`：QProcess MergedChannels → Build Log 通道（运行前 `showChannel(ChannelBuild)`），
  打印 `--- Running: <abs path> ---` 与 `--- Program exited with code N ---`；
  **子进程 PATH 前置 kMingwBin**（产物动态链接 libstdc++-6/libgcc_s/libwinpthread）；
  工作目录 = 源文件目录；**在 `started()` 信号里 `closeWriteChannel()`** ——
  程序没有终端，主动给 stdin EOF，否则 scanf/getline 会永久阻塞（start 之后立刻 close 无效，
  那时通道还没建立）。
- `updateRunActionStates()`：编译中禁用 Compile/Compile&Run/Run；运行中禁用 Run/Compile&Run、
  启用 Stop。`closeEvent` 里除了 kill 编译器，也 kill 运行中的程序。

## 括号自动配对（CodeEditor）
用户诉求：输入时自动匹配另一个括号。

- `CodeEditor` 新增（`.hpp` 里加 `#include <QTextCursor>`）：
  - `autoCloseBracket(QChar typed)` → bool（是否已消化这次按键）
  - `backspaceEmptyPair()` → bool
  - 静态工具：`closingBracketFor()` / `isClosingBracket()` / `isQuote()` /
    `characterBefore(cursor)` / `characterAfter(cursor)`。
- 行为：`(` `[` `{` `"` `'` 插入成对、光标居中；**已有右半边则跳过它**（否则会得到 `())`）；
  有选区则**包裹**选区并保留选中状态；`"` 不配对时退回普通输入。
- `characterAfter()` 必须用 `position() >= characterCount() - 1` 判断结尾
  （QTextDocument 末尾有一个段落分隔符 `U+2029`，文档 `"()"` 的 characterCount 是 3）。
- **坑（backspaceEmptyPair 第一版有 bug）**：想删除 `(|)` 时用
  `movePosition(PreviousCharacter, KeepAnchor, 2)` —— 从 position 1 出发左移 2 个字符
  会**停在文档开头只选中 1 个字符**，结果只删掉 `(` 并把光标留在错误位置（`foo(|)` → `fo)`）。
  正确写法：`setPosition(pos - 1)` 再 `setPosition(pos + 1, KeepAnchor)`，最后 `removeSelectedText()`。
- 选区包裹**不能**用 `selectedText()` 重新插入：它会把段落分隔符变成字符 `U+2029`，
  多行选区会被写坏。改为在 `selectionStart`/`selectionEnd` 处分别 `insertText` 前后两半。
- 引号特例：前一字符是字母/数字/下划线且后面不是同种引号时**不配对**
  （C++ 的 `1'000` 数字分隔符、注释里的撇号、`foo"`）。
  **坑**：这条守卫必须带 `!cursor.hasSelection()` —— 选区存在时 `characterBefore()`
  取到的是选区前的字（如 `"foo"` 里的 `o`）而 `characterAfter()` 是段落符，
  守卫会把 `"` 对选区的包裹也拦掉，退化成"用 `""` 替换掉选区"。
- 在 `keyPressEvent` **最前面**拦截（早于补全逻辑），让自动插入的对表现得像普通输入
  （一次 undo 就能整体撤销）；`plainTextKey` 排除 Ctrl/Alt/Meta 修饰键。
- `"` 配对后仍要调 `requestCompletionAtCursor("\"")`：`"` 兼作 clangd 的 include 补全触发符，
  直接 `return` 会把原来的补全入口丢掉（回退到旧代码会插出第二个引号）。
- 验证：离屏 headless 测试 `%TEMP%\lightcpp_smoke\bracket_smoke.cpp`，
  用 `QKeyEvent` 真实驱动 `CodeEditor`，**31 项断言全过**（插成对 / 引号不配对 /
  跳过右半边 / 包裹选区 / Backspace 删空对 / 一次 undo / 只读文档不响应）；
  ctest 67/67 通过。
