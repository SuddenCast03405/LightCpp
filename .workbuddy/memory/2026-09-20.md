## 添加语法检查功能（clangd via LSP）

### 架构
新增 `LightCpp::App::LanguageServerClient`（QObject）：
- QProcess 启动 clangd（`--background-index=false --clang-tidy=false --pch-storage=memory`
  轻量模式）
- LSP base protocol：`Content-Length: N\r\n\r\n{json}` 帧解析
- initialize/initialized 握手 → didOpen/didChange(全文同步)/didClose
- 接收 `textDocument/publishDiagnostics` 推送，解析出 `LspDiagnostic`，
  发出 `diagnosticsReady(filePath, QList<LspDiagnostic>)` 信号
- stop()：发 shutdown 请求 + exit 通知，1.5s 超时后 kill
- 启动子进程时把 clangd 所在目录加到子进程 PATH（MSYS2 clangd 依赖同目录 DLL）

- Tools 菜单加"语法检查"checkable action（`actSyntaxCheck_`）
- 构造函数创建 `lsp_` 与 800ms 防抖 timer
- 打开 C/C++ 文件后调 `lsp_->openDocument`
- 编辑器 textChanged → `scheduleLint(editor)` → timer → `lsp_->changeDocument`
- `diagnosticsReady` → 找到对应编辑器 `setDiagnostics` + 输出面板显示错误/警告计数
- 关闭标签 → `lsp_->closeDocument`
- `actSyntaxCheck_` 关闭时停止 LSP 并清空所有编辑器诊断标记

### CodeEditor 诊断显示
- `setDiagnostics(QList<LspDiagnostic>)` 存诊断列表
- `updateExtraSelections()` 合并当前行高亮 + 诊断下划线
  - 错误（severity=1）红色波浪下划线
  - 警告（severity=2）琥珀色波浪下划线
  - 信息/提示（3/4）灰色波浪下划线
  - QTextCharFormat::setToolTip 让 hover 显示错误消息
- `lineNumberAreaPaintEvent` 在行号左侧画红/黄圆点（按行取最严重诊断）
- LSP 的 line/character 是 0-based + UTF-16 code units，QTextDocument 内部一致，可直接索引

## 修复未保存文档无语法检查 (2026-09-20)

### 问题
用户在 Untitled 文档输入代码没有任何诊断——`onLintTimerTimeout` 里
`filePath` 为空直接 return，未保存文档永远不会推送给 clangd。

### 修复：虚拟 lintPath
clangd 一切以文件 URI 为 key，给未保存文档分配虚拟路径即可：
- `CodeEditor` 新增 `lintPath_` 成员：`setLintPath()` / `lintPath()`
  （lintPath 为空时回退 filePath()）
- `onNewFile()` 给 Untitled-N 分配 `QDir::tempPath()/lightcpp-untitled/Untitled-N.cpp`
  （.cpp 扩展名决定 clangd 解析模式，文件不落盘）
- `onLintTimerTimeout` / 诊断匹配 / `onCloseTab` / serverStarted 打开 tabs
  全部改用 `lintPath()`
- `onSaveFile` 保存成功后：didClose 旧虚拟路径 → setLintPath(真实路径) →
  didOpen 真实路径（重新同步）
- `LanguageServerClient::changeDocument` 若文档未 open，自动补发 didOpen
  （languageId 按扩展名推断，内部 `languageIdForExtension()`）

## 修复关闭 clangd 时 IDE 崩溃 (2026-09-20)

### 根因
`LanguageServerClient::stop()` 流程：
1. `process_ = nullptr`（detach 局部变量 proc）
2. `proc->waitForFinished(1500)` 阻塞等 clangd 退出
3. waitForFinished 内部 spin event loop，期间 QProcess::finished 信号被分发
   到 `finished` lambda
4. lambda 访问 `process_->deleteLater()` —— 但 process_ 已被置 nullptr，
   **nullptr 解引用崩溃**

### 修复
1. **stop() 开头先 `process_->disconnect(this)`**：断开所有 process → this 的
   信号连接，让 waitForFinished 期间没有 lambda 能触发
2. **finished lambda 改用 `sender()` 不依赖成员指针**：即使 disconnect 失效
   或自然结束时，也安全
3. **errorOccurred / aboutToClose lambda 加 nullptr 检查**：兜底

### 验证
- 编译通过，全量 67/67 测试无回归，GUI 启动正常（PID 628）

## 添加语法补全 (2026-09-20)

### 范围
基于 LSP `textDocument/completion` 实现补全：触发字符 (`.` `:` `>`) 自动弹出 +
Ctrl+Space 手动触发；用户选条目后替换光标前标识符。

### 实现
- **LanguageServerClient**：
  - initialize 声明 `completion` capability（triggerCharacters=`. > :`，resolveProvider=false）
  - `requestCompletion(filePath, line, column, triggerChar)`：构造 LSP 请求，
    triggerKind=2 当 triggerChar 非空；返回 JSON-RPC id 给调用方跟踪
  - `handleMessage`：响应里有 id 且在 `completionRequests_` map 中→解析
    CompletionItem[] 或 CompletionList.items，emit `completionReady(id, filePath, items)`
  - `LspCompletionItem{label, detail, documentation, insertText, kind}`；insertText
    优先用 textEdit.newText，否则用 insertText，再退到 label
- **CompletionPopup**（QListWidget 子类，Qt::Popup）：
  - `present(items, globalPos)`：列表显示 label + 类型首字母（f=Function/M=Method/T=Class 等），
    detail/documentation 作为 tooltip
  - 大小：宽 ≥220 或最大条目宽+40；高 = 行高 × min(count, 12)
  - 屏幕边缘自动重定位（防止超出右/下边）
  - `filterByPrefix`：按 label 前缀过滤（大小写不敏感），无匹配则关闭
  - 键盘：Enter/Tab 接受当前条目，Esc 关闭，Up/Down 走 QListWidget 默认
  - 其他按键通过 QApplication::sendEvent 转发给父 CodeEditor
- **CodeEditor**：
  - 构造函数创建 popup_，连接 itemAccepted → applyCompletionItem
  - `keyPressEvent`：Ctrl+Space→requestCompletionAtCursor("");
    popup 可见时拦截 Enter/Tab/Esc/Up/Down/PageUp/PageDown/Backspace；
    触发字符或标识符输入时先让 QPlainTextEdit 处理，再 requestCompletionAtCursor
    或 refreshPopupFilter
  - `requestCompletionAtCursor`：从 textCursor 取 blockNumber/positionInBlock，
    emit `completionRequested(line, column, triggerChar)`
  - `applyCompletionItem`：若光标前是触发字符（`.` `:` `>`）直接 insertText；
    否则选中并替换光标前的标识符前缀
- **MainWindow**：
  - lsp_ 初始化块连接 `completionReady` → 按 requestId 在 `pendingCompletions_`
    map（`QMap<int, QPointer<CodeEditor>>`）中找发出请求的 editor → `presentPopup(items)`
  - `createEditorTab` 连接 `completionRequested`：用 QPointer 捕获 editor，
    lookup ed->lintPath()，调 `lsp_->requestCompletion`，把返回的 reqId 存入
    `pendingCompletions_[reqId] = editor QPointer`
  - `onSyntaxCheckToggled(false)`：清空 `pendingCompletions_` + 各 editor `dismissPopup()`
  - QPointer 防止 tab 关闭后响应回来用悬空指针

### 踩坑
- `QByteArray::startsWith(str, Qt::CaseInsensitive)` 在 Qt6 中不存在，已改用
  `toLower().startsWith(...)`
- `QWidget::raise_()` 不存在，是 `raise()`（之前笔误）
- `displayText` 函数定义未使用，-Werror 下报错；删除

### 验证
- 编译通过，全量 67/67 测试无回归，GUI 启动正常（PID 1424）

## 修复补全只在触发字符后出现/仅 include 有补全 (2026-09-20 第二次)

### 问题
1. popup 只在打完 `>` 后出现：触发字符只有 `. : >`，`#include<` 的 `<` 不触发
2. 只有预处理补全有结果：**竞态**——补全请求在触发字符后立即发出，而编辑器
   文本经 300ms 防抖才 didChange，clangd 看到的是缺刚打字符的旧文本，
   位置对不上返回空

### 修复
- **MainWindow completionRequested 处理器**：调 requestCompletion 前先
  `lsp_->changeDocument(lintPath, ed->toPlainText())` 立即推送当前全文，
  消除竞态（changeDocument 内部对未 open 文档自动补 didOpen）
- **CodeEditor keyPressEvent**：
  - 触发字符扩为 `. : > < "`（`<` `"` 触发 clangd include 补全；
    include 上下文外 clangd 返回空列表，popup 不显示，无副作用）
  - 标识符字符（字母/数字/下划线）插入后启动 `completionIdleTimer_`
    （200ms singleShot）——"边输入边补全"，无需触发字符
  - Esc/其他字符 stop 定时器，防止光标移动后误弹
- **LanguageServerClient initialize**：triggerCharacters 扩为 `[".", ":", ">", "<", "\""]`

## 修复补全奇偶交替消失 + 提速 (2026-09-20 第三次)
### 现象
`#i` 弹 → `#in` 不弹 → `#inc` 弹，严格交替；且整体偏慢。

### 根因
1. popup 打开时只做客户端过滤、**从不重新请求**；popup 关闭时才靠空闲定时器
   发请求。任何"过期的空响应"（如打完 `#include` 完整词时定时器发出的请求，
   clangd 对无 `<`/`"` 的上下文返回空）晚到都会把 popup 关掉 → 弹出与否
   取决于过期响应与打字节奏的赛跑 → 奇偶交替。
2. 空闲定时器 200ms 偏慢。

### 修复（VS Code 风格重调度）
- **每次编辑都重新请求**：标识符输入与 Backspace 在 popup 打开/关闭两个分支
  都重启 `completionIdleTimer_`（120ms singleShot）→ 定时器到点发新请求；
  popup 开关状态不再影响是否请求 → 奇偶交替不可能发生。
  保留 `refreshPopupFilter()` 作即时反馈，clangd 新响应到达后整体刷新。
- **过期响应守卫**：MainWindow 新增 `latestCompletionId_`（最新请求 id）；
  `completionReady` 中 `requestId != latestCompletionId_` 一律忽略（从
  `pendingCompletions_` 移除但不呈现）→ 旧空响应无法关闭新弹窗。
- **空闲 200ms → 120ms**。
- **mousePressEvent**：编辑器内点击关闭 popup 并停定时器（否则定时器在
  新光标位置误触发）。

### 验证
- 编译通过，全量 67/67 测试无回归，GUI 启动正常（PID 314）

## 悬停显示诊断 tooltip (2026-09-20 第四次)

### 需求
鼠标放到错误/警告/信息/提示（波浪线标记的）文字上时显示诊断内容。

### 根因
`QTextCharFormat::setToolTip` 对 extra selection 无效——extra selection 只是
绘制覆盖层，文档文本布局不知道它，悬停事件带不出 tooltip。

### 实现
- CodeEditor 重写 `event(QEvent*)` 拦截 `QEvent::ToolTip`：
  - `cursorForPosition(helpEvent->pos())` 取光标位置（ToolTip 事件的 pos
    是 viewport 坐标，正好匹配 cursorForPosition）
  - 与 `diagnostics_` 匹配（LSP 0-based UTF-16 code units，与 QTextCursor
    同一坐标系可直接比较）：单行范围检查列区间；零宽范围（end<=start）接受
    整行；多行范围只在边界行检查列
  - 重叠时取最严重（severity 最小）的诊断
  - tooltip 文本：`[Error|Warning|Info|Hint] 消息 (code)`，QToolTip::showText
  - 未命中则 QToolTip::hideText + event->ignore()；`QEvent::Leave` 时 hideText
- 踩坑：`LspDiagnostic` 忘写 `LightCpp::App::` 限定编译失败
- 踩坑：本机 Bash 没有 cat/heredoc，追加记忆日志要用 Read+Edit 工具

## 修复零宽诊断渲染（红点跑到下一行 + 无波浪线）(2026-09-20 第五次)

### 现象
输入 `#include`（缺文件名）时：无波浪线，红点显示在下一行（空行）。

### 根因
clangd 对这类"缺参数"错误报**零宽 range**，且位置在错误行的**下一空行第 0 列**
（指向 past-the-end）。后果：
1. 行号红点直接画在空行上（startLine 就是空行）
2. 波浪线 selection 选中换行符 → 画出来不可见

### 修复：normalizedDiagnostic() 归一化（三处共用）
- **归一化规则**：零宽 && 列 0 && 行 > 0 && 目标行是空行（length<=1）→
  归属到上一行行尾（startLine-1, prev.length()-1）
- **updateExtraSelections**（波浪线）：零宽区间选一个可见字符——
  在行尾/超出行尾时取该行**最后一个字符**（与其他编辑器 squiggle token
  尾部一致）；否则取光标处字符；空行无可选字符时跳过 selection（红点仍显示）
- **lineNumberAreaPaintEvent**（红点）：lineSeverity 用归一化后的 startLine
- **event() 悬停匹配**：用归一化后的区间匹配（顺便修了 hit 悬空指针——
  改为循环内维护 `hovered` 值拷贝，severity==0 表示未命中）
- 效果：`#include` → 红点回到第一行，`include` 尾部出现红色波浪线，
  悬停显示 `[Error] Expected "FILENAME" or <FILENAME> (pp_expects_filename)`

### 踩坑
- lightcpp.exe 在运行时构建复制到 dist/ 报 Permission denied——先 Stop-Process

- 编译通过，全量 67/67 测试无回归，GUI 启动正常（PID 912）
