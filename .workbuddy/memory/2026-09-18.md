## 本机构建环境要点（重要，后续直接复用）

- 工具链：`E:\msys64\ucrt64\bin`（gcc/g++ 16.1.0、cmake 4.3.3、ninja 1.13.2）。**未安装 Qt6**
  （`E:\msys64\ucrt64\lib\cmake\Qt6` 不存在），所以核心逻辑层刻意做成无 Qt 依赖。
- Bash 工具在本机 PATH 损坏（ls/grep/head 都 command not found）→ **统一用 PowerShell 执行构建**。
- PowerShell 的 stdout 有时被吞 → 需要结果就 `Set-Content -Path xxx.txt -Encoding UTF8` 再读文件。
- 运行 cmake/g++/exe 前必须 `$env:PATH = "E:\msys64\ucrt64\bin;" + $env:PATH`。
- 网络：github.com 的 `git clone` 与 release 下载超时/失败；**`raw.githubusercontent.com` 和 `codeload.github.com`
  可用**（`Invoke-WebRequest`）。因此 CPM.cmake 与 GTest 都是手动下载后放本地：
  - `cmake/CPM.cmake`（v0.40.2 正式版）
  - `third_party/googletest-1.14.0/`（解压自 codeload 的 tar.gz），CPM 用 `SOURCE_DIR` 引用，可离线配置。
- 解压 tar.gz：`C:\Windows\System32\tar.exe -xzf`（msys 的 tar 缺 gzip 会失败）。
- **ctest 坑**：MinGW 动态链接时 ctest 只有第 1 个用例能跑，之后全部 `0xc0000135`（DLL 找不到）；
  手工连续跑 exe 正常。解决办法：测试可执行文件加 `-static-libgcc -static-libstdc++`，
  之后 `ctest --preset msys2-ucrt64` 28/28 全通过。以后新增测试目标建议同样静态链接运行时。
- 严格警告 `-Wall -Wextra -Werror` 只挂在 `LightCppWarnings` INTERFACE 目标上并链接到自有目标，
  避免 CPM 拉进来的第三方源码被 -Werror 打断。
- 易踩坑：C++ 十六进制转义贪婪匹配，`"\xFEend"` 里的 `e` 会被当成 hex 数字 → 必须拆分字面量
  （`"ok\xFF" "\xFE" "end"`）。
